# How the app.appbar contract was written, and what its props make the harness do

Based on: Draft A and Draft B of app.appbar, the critique, and the sources the drafts cite (title-bar.json, features-title-bar.txt, F02/F09 records, notes-title-bar.txt, web.md, decisions.md, contract-format.txt, index.txt). The source files were not reopened for this merge; facts come from the drafts and the critique.

Props (merged meaning for the harness):
- dataset (string, default standard): before mounting, the harness signs in as the demo account and loads the named demo set. standard = Home with Errands, Reading, Garden; Spring launch with Website, Press kit. empty = Home with one list, Inbox. nolists = Home with no lists. The value long is dropped: its 40 tasks sit in Errands and never appear on the bar, and no dataset overflows the tab strip, so no bar check can use it (F02-058 stays untestable).
- reducedMotion (string, default "off"): changed from boolean per the critique, because decision 16 is three-way. Before mounting, the harness sets the account's Reduced motion choice to On ("on"), Off ("off") or System ("system"). The indicator shows only for On. The "system" value has no test: the spec files give no way to set the OS reduced-motion preference, so System is recorded as not measured. The default "off" is kept from both drafts (their false default); the spec does not state the account default.

Events: one shape per event, taken from Draft A (request events, and the critique's boundary that the bar emits requests). Dropped from B as commit events owned by the sheets: projectCreated, projectRenamed, projectDeleted, listCreated, listDeleted. Dropped from B as a duplicate of listExportRequested: listExported. Shape conflicts resolved to A: panesSwapped (left string, not a count), settingsOpened and trashOpened (open boolean, not a count), signedOut replaced by signOutRequested (signedIn boolean). listRenamed stays because the inline rename commits on the bar itself.

Parts: one name per control, clearer name chosen. projectSwitcher (B) for project; listTabs (A) for the strip; listRenameInput (A) for tabRenameInput; splitView (B) for split; previewToggle (B) for preview; trashButton, paletteButton, settingsButton, accountButton (B) for the web buttons; accountSignOut (B) for signOut; reducedMotionStatus (B, role status) for the indicator; projectRowSpring (B) and projectRowSpringLaunch (A) merged. Rows are button parts with the menuitem role in the comment (A's menuitem, not B's option). Parts with the generic role carry a real ARIA role in the comment (paneMarker as img, accountEmail as none). Sheet parts (sheetName, sheetRoll, sheetCancel, sheetConfirm) and commandInput are not in this contract (see moved tests below). keyboard is true again, as the critique asks. Viewport height is 160 for both widths (A's value; both fit the menu bottom at y 154).

Tests: union of A and B with duplicates removed. Kept from A: the full list of inline rename, tab menu, split, preview, web button and account tests. Added from B: next and previous project chords (both directions), next and previous list chords, Alt+Digit2, the Spring launch delete request, the split-off-from-tab-menu test, the switching-project-clears-split test. Added from the critique: a tab click with split on does not swap (F09-020). Changed: the re-press test is dropped (see open issues). B's exact tab-menu name patterns are replaced by A's exact names. Key names use one code-name form (Digit2, KeyN, BracketRight, ArrowLeft) with Alt; the literal Control and K are not used. Duplicates dropped: B's clicking Reading (Garden kept), B's double-click on Reading (A's Errands kept), B's inline Enter, Escape, leave and empty tests (A's kept), B's Settings in the account menu (A's kept), B's duplicate narrow test (A's kept), B's sign-out count check (A's request check kept), B's list delete check on Errands (A's Reading kept), B's outside press on the switcher (A's press on preview kept, with an explicit side effect).

Moved out of this contract (no sheet or palette contract exists in this merge; they belong in those contracts): project rename sheet (typed name, Enter commits projectRenamed, Escape cancels); new project sheet (celestial single-word name, Cancel creates nothing, projectCreated); delete project sheet (Cancel focused, Enter does not confirm, Space confirms, Escape cancels, count text); new list sheet (adjective plus noun name, Enter creates, Escape cancels, roll another name); list delete confirmation (Cancel focused, Enter does not confirm, Space deletes, Cancel keeps, count text for Errands and Spring launch); menu Rename through the sheet (Enter commits listRenamed); command palette (field focused on open, Escape closes, Mod+K chord); Settings modal close (Escape and close button, 640x520, per web.md). Export file content is not measured (browser download).

Conflicts and how they were resolved:
- Decision 18 (web chords): Notes A say it is not on this bar; the critique and Draft B say the bar owns the switcher and tab chords (F09-011, F09-012). Followed the critique: chord tests are in. The palette chord (Mod+K) is left to the palette contract.
- F02-006 and the inventory (ProjectSwitcher.tsx:31, 120-123) disagree on whether re-pressing the pill closes the menu. The critique says F02-006 does not contradict itself; the conflict is between the feature record and the inventory. The re-press test is dropped and recorded as an open decision.
- Shortcut hint: Notes A cited F09-074 and F02-020 for "main-default has no hint". The critique says F02-020 only says hints vary between states. The hint text is not asserted because the inventory widget and elements.json show "Settings  ⌘," in main-default while the feature records do not settle it.

Left out on purpose:
- Desktop-only items dropped on web (web.md): F02-001, 003, 023 to 031, 059, 060 (traffic lights, caption buttons, grip, drag region, double-click maximize); the Low Power tooltip variant of the indicator; the Settings window (now a modal).
- Drag-and-drop of tabs and tasks: drag acts only on sliders.
- Middle-click delete and pointer right-click: no action in the format. The ContextMenu key on a focused tab is used instead.
- Ctrl/Cmd+K and Settings shortcut hints: app-level, not on this component.
- Tooltips and shortcut hint text: conflicting sources (see above).
- Dark colours: no dark state recorded (F09-092).
- F09-032 (split only with two lists): the one-list split result is not in any file, so it is not tested; recorded as not measured.
- F09-099 localStorage part of split reset: not measured.
- F09-001, 002 (import needs a file picker), F09-017 to 019, 022 (restart persistence), F09-027 to 035, 043 to 056, 076 to 092 (other screens).
- F02-040 pane icons, F02-022 styling, F09-097 hover handler: visual only, covered by the screenshot tests and selected checks.
- F02-008: a reference tree mismatch, not a behaviour.

Open issues:
1. The re-press conflict above. If the decision is that re-pressing the pill closes the menu, add the test back; if not, keep it out.
2. The reference screenshots are desktop captures with the macOS cluster and the grip, which the web drops. The web screenshots will differ there. Nothing is masked (no parts exist for those areas). Re-capture the reference for web, or add parts so the area can be masked.
3. modifierHold, the ContextMenu key mapping, the two-press double-click and the Alt chord key names are assumed from their names and the critique, not checked against the platform files.
4. The empty-dataset test assumes Inbox is selected on mount.
5. The outside-press tests (preview press on the project menu; Garden press on the tab menu) assume the press passes through to the control and toggles or selects it. If the build swallows the press, change the event counts to 0.
6. The role mapping for paneMarker (img) and accountEmail (none) is an assumption where the drafts give no role.
7. The System reduced-motion value is not measured (see above).
