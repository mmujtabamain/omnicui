# Review notes on the filter-panel screen (the team's comments and how each was settled)

- [both] Haiku critic: The task list search bar has no widget entries for three features the panel must keep: the clear-search control (F05-032), the result count inside the input well (F05-059), and the no-match empty state that replaces the task list (F05-061). Add a widget entry for each, with its visibility rule, so the rebuild does not drop them.
  - reply (Haiku review): Answered. The three features exist in the reference and stay as conditional entries, not new widgets. Clear search (F05-032) is a plain IconButton, close icon at size 15, titled "Clear search", shown only while the trimmed query is non-blank; it clears the query and keeps scope and fields. The result count (F05-059) is a muted semibold 11px label shown only when query.trim() is non-empty, and the no-match EmptyState (F05-061) uses search_off at size 30 with title "No matches in <list name>" when a search is active and no root task is visible.
- [both] Haiku critic: The same tune glyph is used for two different jobs: the Search options button at 784,63 in the search bar, and the Sort & filter ViewControl at 12,735 in the footer, which opens this panel. The inventory says Search options is not the panel opener but leaves its purpose unconfirmed. Pick a distinct icon for search options, or record what it opens, so the panel opener is unambiguous.
  - reply (Haiku review): Decided. Decided: the Sort & filter opener keeps the tune glyph, and the Search options button gets a different Material Symbols glyph (for example manage_search). Search options is not a panel opener; its menu sets search scope (This list, Whole project, All projects) and fields (Title & notes, Title only, Notes only), which settles the inventory's uncertain note as not opening this panel. Record Search options as the scope and fields menu in the inventory.
- [both] Haiku critic: The hidden chevron_left at 771,246 has behaviour 'Unknown', yet feature F05-066 says parent rows show an expand chevron beside the done counter. Record it as the expand or collapse control for subtasks, with its states (collapsed and expanded), since the rebuild needs it and it is currently only inferred.
  - reply (Haiku review): Answered. The hidden chevron_left is the expand/collapse control for a parent task. It is a button whose click calls toggleCollapsed(task.id), titled "Expand" when collapsed and "Collapse" when expanded. Collapsed, the chevron is unrotated and always visible; expanded, it is rotated -90 degrees at opacity 0 until the row is hovered, which is why it is absent from the screenshot where Buy groceries is expanded. Update the inventory's Unknown behaviour to this.
- [both] Haiku critic: The Done primary button has a 7px corner radius while the other buttons in the panel (Reset, the sort and date menu buttons, the segmented controls) use 4.375px. Nothing in the inventory gives a reason for this difference. Confirm whether it is intended; if not, use the shared radius so the footer matches the rest of the panel.
  - reply (Haiku review): Answered. No change is needed: the radius difference comes from the shared widget, not from a one-off value. The primary Done button is the shared Button with base class rounded-control (7px, F05-025), while Reset is a ToolbarButton with rounded-field (4.375px), as are the sort, date and direction menus and the segmented controls. Keep the shared widget radii rather than overriding the Done button.
- [both] Haiku critic: The Reset ToolbarButton is described as resetting 'all filter, sort and refine settings', which omits the Date section. Feature F05-051 and the anyActive status dot both imply Date is included, so the purpose text, the enabled-state rule and the behaviour disagree. Correct the description to state that Reset clears sort, show, refine and date for every target list.
  - reply (Haiku review): Answered. The Reset description is wrong: Reset removes the stored view entry for every visible target list or pane (both panes while split), which covers sort, show, refine, date field, date range and day count; a pane with no stored view is unchanged. It is enabled while sort, show, refine or date range is non-default, but not when only date field or day count differs. Replace the description with: "Resets the stored view for every visible target list (sort, show, refine, date field, date range, day count). Enabled while sort, show, refine or date range is non-default."
- [web] Haiku critic: The Hide preview panel button (accessible label with the shortcut Cmd+\) and the Settings button (Cmd+,) both advertise global-style shortcuts. The web build must let browser shortcuts take precedence and has no global hotkeys, so these shortcut hints should be removed or mapped to in-app keys that do not clash with the browser.
  - reply (Haiku review): Decided. Decided for the web build: remove the ⌘\ hint from the Hide preview panel tooltip and the ⌘, hint from the Settings tooltip. The web build has no global hotkeys and browser shortcuts take precedence, so it must not advertise chords it does not receive. The desktop build keeps both hints because the reference binds them.
- [both] Haiku critic: The Refine rows (Notes, Attachments, Subtasks) use a Segmented size=sm with Any, With, Without, while the Show and Date segmented controls use the default size for their three or two options. The same kind of choice is styled at two sizes with no stated reason. Use one segmented size for all choice groups in the panel, or document why the Refine rows are smaller.
  - reply (Haiku review): Decided. Decided: every choice group in the panel uses the shared Segmented default size (md, h-6.5, 12px), so the Refine Any/With/Without control changes from sm (h-5.5, 11px) to md. Widen the Refine control rather than shrinking its text, since the inventory already records the Without label as clipped at the current size. If the width cannot fit, a label-above-control row layout (raised by the second reviewer) is the fallback.
