Props, with the merged harness meaning:
- dataset (standard by default; empty, nolists, long): the harness seeds the local SQLite database with that set. This screen reads only settings and the data path, so every set shows the same screen. The tests use the default.
- open (capture by default; general, shortcuts, about): the harness presents the window with that sidebar section selected, set as a user click would set it.
- storedScreenshotMode (fullscreen by default; region; any other text): the harness stores the value as screenshot_mode before the window opens. Any value other than fullscreen or region must show Full screen. Draft B reached F10-032 only through the datasets, which hold no stored region; this prop replaces that route, so the fallback test is reachable.
- pathLoading (false by default; true): the harness holds the data-path reply, so Saved to shows the dash. Draft B said the dash could not be reached; draft A holds the reply, so the dash test is kept.

Events (merged):
- settingSaved (key, value): the app's write of screenshot_mode through ctx.set or ctx.discard. Draft B's screenshotModeChanged (mode) observed the same write, so it is dropped as a duplicate. Both drafts assume the discard writes and emits this event; that is not verified.
- folderOpenRequested (folder): replaces draft B's pathOpened (path). Draft B carried the absolute machine-specific path; folder "screenshots" is machine independent.
- windowClosed (reason): kept from draft B. Draft A left the Escape close out as an OS action, but the rules allow testing an app handler that calls close(), so the event is kept. Confirm.
