BASIS. Merged from Draft A and Draft B, with the critic's fixes applied. No source, feature record, platforms.yaml or format document was opened in this merge, so every choice below rests on the two drafts, their notes and the critique. Items the drafts left unverified are marked as such.

PROPS (what the harness does).
- dataset (standard | empty | nolists | long): loads that demo set from spec/screens/web.md into the one local SQLite database. standard gives the target "Home / Errands". empty gives "Home / Inbox" (per the critique, the first list of the Home project). nolists has no lists; a submit there is asserted only by its count and the barHidden event, because the generated list name is not fixed. long is not used by any test.
- draft (empty | typed | notes): seeds the draft before the first frame and emits no draftChanged for the seed. empty = no title, notes closed. typed = title "Call the plumber", notes closed. notes = title "Call the plumber", notes open and empty. The title of the notes state is an assumption (the reference does not state it), and the tests that use notes depend on it.
- captureResult (captured | cancelled | failed | pending): how the harness answers a screenshot request (the native grab cannot run headless). captured = one PNG at once. cancelled = the region selection is cancelled: no image, no error. failed = an error, shown as "Capture failed". pending = never resolves during the test, so the button stays disabled and the spinner stays. Draft A called these ok, hold, fail and cancel; the names of Draft B were kept because they are clearer.
- Viewports: 760 x 116 is the collapsed card and the starting size. 760 x 185 is the notes-open size (F13-039, F14-032). The harness reads the live window size and must not crop it. The critique asked for a second viewport, so both are listed; whether the format runs every test at both sizes is unknown and is flagged.
- colorSchemes [light, dark]: the first test is the reference dark state.
- keyboard: true. The screen is keyboard driven (Tab, Enter, Escape, Shift+Enter). Enter on a focused footer button is not tested. Draft B cited F13-003 for a submit from a footer button, but the feature title of F13-043 (as Draft B quotes it) says the card handles only title and editor keys, so no footer submit is expected. Footer buttons are tabIndex -1 per the review.

EVENTS (the bar's own observable effects, plain text, notes "" when there are none).
- draftChanged (title, notes, shots): after each change of the draft.
- taskSaved (title, notes, shots, project, list): a submit. Notes and shots were added at the critique's request, so the notes and the attached shots are checked.
- barHidden (title, notes): the bar hid, with the draft it still holds. A submit emits it with the cleared draft; Escape and the footer target emit it with the kept draft.
- mainRequested (project, list): the footer target asked for the main window. This is Draft A's event; Draft B's mainOpened was dropped as its duplicate.
- captureStarted (pending): a native grab was requested; pending is the in-flight count after the request. Added from Draft B for the second-press check (F14-009).
- Draft B's submitted and dismissed were dropped (replaced by taskSaved and barHidden, which carry the project, list and notes fields that Draft B lacked).

PARTS. Names are the clearer forms of the two drafts: notesHint (Draft A's hint), strikethrough, bulletList and numberedList (Draft A). Roles follow the allowed set. card is aria dialog, toolbar is aria toolbar, and both are generic. spinner is required (critique), so a test that expects it hidden assumes that a part which is not rendered counts as not visible; this is flagged. notes and the footer buttons follow the same assumption.

NAMED INPUTS.
- submit (existing, in the list): used for the Cmd/Ctrl+Enter tests (decision 20). Draft A flagged that its binding in platforms.yaml is unverified. If it is not the platform modifier plus Enter, rename the two tests to a new input submitMod (default Control+Enter, macos Meta+Enter). Draft B's modEnter was not added, because it would duplicate submit.
- clearDraft (proposed, not in the list): default { key: Control+Shift+Backspace }, macos { key: Meta+Shift+Backspace }. Reason: the reference clear accelerator is Cmd+Shift+Backspace, active with the title or the notes focused (F14-023). The feature title F13-013 says Cmd+Shift+Delete. The conflict is kept open; the code default is used. The platforms.yaml entry must be added by the harness owner.
- selectAll (existing) is used for the formatting and list tests.
- summon (Draft B) was not used. The reveal is the native shell's contract, and the critique says a do action is allowed only when the target advertises it, which is unverified. The reveal-focus and survives-reveal tests were dropped.

CONFLICTS AND DECISIONS.
- Counter: "0/2000" (code and screenshot, per the critique) versus "0 / 2000" (elements.json). The exact "0/2000" is used, per the critique.
- Target label: the regex ^Home ?/ ?Errands$ is kept, because the separator may have no spaces. The exact text must be measured once and pinned.
- Footer target and hiding the bar: Draft B expects the bar to hide (dismissed), Draft A did not check it. Draft B's source (its reading of F13-017 and F14-043) is the more precise, so the barHidden expectation is kept and flagged as unverified.
- Submit (decision 20): taken from F14-046 (the bar is dismissed and the draft cleared). Draft B noted that F13-015 describes only the clear. Flagged as uncertain.
- Clear visible in the notes state: the notes-state test has a title, so Clear is expected. Whether Clear shows with an empty title and open notes is unresolved and not tested.
- Placeholder: the code says "Capture a task ..." and the screenshot shows an ellipsis. The placeholder is not asserted; the screenshot covers it.
- Screenshot button filled state is neutral, not accent (review note). This follows decision 12 (accent only for the primary action and selection) and the review note, not the accent wording of F13-026 alone. Covered by the screenshot tests.
- Hint and Clear keep their roles per the review: the Tab hint is in the tab order (F13-007); Clear, target and screenshot are tabIndex -1. Clear's tabIndex comes from the review notes only and is marked unverified.
- Notes state: "formatting button keeps empty notes open" may conflict with F14-055 (empty notes collapse when the editor is left). Kept and flagged.
- Escape, submit and footer hide the bar; the draft is kept on Escape and the footer target, and cleared on submit (F14-046, F13-015).

UNCERTAIN ITEMS (kept as written, flagged).
- times: 0 on events is used in several tests. The format's allowance for zero is unconfirmed (both drafts used it).
- focused: false and selected: true on the toggle buttons assume the format and the ToolButton active state support them (both drafts).
- The second press on a disabled screenshot button (pending test) may be refused by the harness as a press on a disabled element. If so, the test should use a focus-and-press or be split.
- Enter in the notes is taken as a newline, and the notes text "Milk\nEggs" is compared as plain text. The editor code was not read.
- Hover tests check only visible: true. The hover colour is not a field, so the hover state is checked by the screenshot alone.
- The 300 px cap on the notes (F13-008) is checked by the long-note screenshot only; no height is asserted.
- Dividers and the vertical separators are estimated from the screenshot; covered only by screenshots.
- Whether the format runs each test at both viewports is unknown. The tests with notes open depend on the live window size, not on the viewport entry.
- Dark colour scheme is covered by colorSchemes, not by a separate test.
- Name matchers nested inside platform keys (Draft B) were removed, because the format shows only plain values per platform, and the tooltip tests that used them were dropped.
