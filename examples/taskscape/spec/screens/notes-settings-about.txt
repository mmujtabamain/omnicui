# Review notes on the settings-about screen (the team's comments and how each was settled)

- [both] Haiku critic: The discard-all control has three different descriptions. The inventory puts an undo clear icon on the Application and Reset SectionHeaders, with a title that says it discards changes since the window opened, and says it may not render. Feature F10-027 places a discard-all (undo) button in the title bar that appears after any change, and F10-034 describes a group header dot that discards changes. Decide one location and one visibility rule for the rebuild, and record the title bar and dot as widgets or remove them from the spec.
  - reply (Haiku review): Decided. There are two discard controls, not one described three ways. The title-bar discard-all shows only while a setting or hotkey has changed since open, and the group header undo shows only when that group has changed; the About groups pass no onDiscard, so only the title-bar control can appear there. Desktop keeps the title-bar control and the group dot; web moves discard-all to the page heading row because it is not window chrome, and the undo clearIcon is removed from the About SectionHeaders.
- [both] Haiku critic: The inventory has no clear-search control for the sidebar search field (widget 'InputWell > TextInput2'). Feature F10-011 requires an x button that appears while the query is non-empty, and F10-010 requires a blue focus outline; neither appears as a widget or state. Add the clear button and the focused-outline state to the search field entry, and state that Escape clears the query first (F10-023).
  - reply (Haiku review): Decided. The reference has a clear-search control (a button labelled 'Clear search' that calls clearSearch, shown while the query is non-empty), and Escape clears the query before closing the window. Add both to the search field entry. The focus outline is not settled by source, and the brief reserves accent blue for the primary action and selection, so the field takes the shared neutral focus ring rather than the screenshot blue in F10-010.
- [both] Haiku critic: The reset job is named four different ways: the row title 'Restore defaults', the button 'Reset all settings…', the confirm button 'Reset everything', and the undo tooltip 'Discard changes made since this window opened'. Pick one verb and noun for the reset control and its confirmation so the rebuilt About pane and the search terms in F10-073 match the visible label.
  - reply (Haiku review): Decided. The 'Discard changes...' wording is the discard tooltip, not a reset label: the window-level tooltip reads 'Discard every change made since this window opened' and the group title reads 'Discard changes made since this window opened'. Keep the row heading 'Restore defaults' (the search anchor), keep the trigger 'Reset all settings…', and change the confirm button from 'Reset everything' to 'Reset all settings' in the danger style. Update F10-068, F10-069, F10-070 and the F10-073 search terms to match.
- [both] Haiku critic: The PathButton entry records only the non-null path and says the null state renders with no path shown, without saying what appears. Feature F10-040 requires a dash while the data folder location is loading, and the inventory has no loading state for this widget. Add the loading and null states, with their exact text, to the PathButton entry.
  - reply (Haiku review): Answered. PathButton renders a muted em dash with no button whenever path is null. Null covers both loading and a failed lookup, because the type stays null while loading and the catch leaves it null. The loaded state is a button with a folder_open icon, the path in monospace, and aria-label 'Open <path> in the file manager'; the version value uses the same dash when null.
- [web] Haiku critic: The Data folder SettingRow, the PathButton and the Application description are tied to a local folder. The web app is cloud-based with server-side files, so there is no local data folder to open, and the description 'Tasks, attachments, screenshots and preferences' names screenshots that the web app does not have. Replace or remove the Data folder row, and rewrite the description to describe only the stored data the web app actually holds.
  - reply (Haiku review): Decided. On web, remove the Data folder row and its PathButton, and remove the Capture settings pane, since its capture mode and screenshots folder are desktop-only. Drop 'macOS' and the menu-bar capture wording from the Application description on both builds, because desktop targets Windows as well as macOS; the replacement tagline is copy for the owner to supply. On web also drop 'capture' from the Restore defaults text.
- [web] Haiku critic: The title bar with the three macOS traffic lights (WindowControls, MacLights, the close, minimize and full-screen Light buttons, and the draggable TitleBar) is window chrome that a browser tab does not have. Drop these widgets in the web build and keep only the 'Settings' page heading, which is the Label h1. The desktop build keeps the chrome, with its inert minimize and full-screen lights as recorded.
  - reply (Haiku review): Decided. On web, drop WindowControls, the three traffic lights and the TitleBar drag region, and keep 'Settings' as the h1 Label. On desktop, keep the chrome as the existing code builds it: the shared TitleBar draws macOS traffic lights on macOS and Windows buttons on Windows, and the panel is non-minimizable and non-maximizable, so the minimize and full-screen lights stay inert. The existing implementation already settles the desktop chrome question, so it needs no product choice.
- [web] Haiku critic: The keyboard behaviour in feature F10-024 and F10-025 conflicts with the web rebuild. Escape closing the Settings window has no meaning in a browser page, and Command-F or Ctrl-F focusing the sidebar search would override the browser's own find shortcut, which the web build must not do. Remove these bindings from the web version and keep the search field reachable by normal focus.
  - reply (Haiku review): Decided. On web, remove the window-level Escape binding that closes the window and the Cmd/Ctrl+F listener, so the browser's own find shortcut works. Keep Escape clearing the search query first, since that is in-page, and reach the search field by normal focus. Desktop keeps both window bindings as the reference has them.
- [desktop] Haiku critic: The window size conflicts between the sources. Feature F10-001 says the Settings window opens at a fixed 640 x 520 size, but the inventory's frame and title bar were measured at 1180 x 760 from the reference screenshot. Confirm the intended fixed size before the desktop build, and record it in the Settings window frame region, because the content pane and sidebar positions depend on it.
  - reply (Haiku review): Answered. The source sets the Settings panel to 640 x 520 and makes that its minimum, so F10-001 should read 'opens at 640 x 520 and cannot shrink below it' rather than 'fixed'. The 1180 x 760 figure matches the main window in tauri.conf.json, so the reference recording was likely taken from the wrong window. Record 640 x 520 in the frame region and re-check the reference recording at that size.
