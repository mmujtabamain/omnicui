# How the app.tasklist contract was written, and what its props make the harness do

BASED ON: the two drafts (A and B), the critic's findings, and the critic's fixes, which were applied. This merge opened no source files. Every fact comes from the drafts and their citations. The critic flagged several of those citations as unverified, and the items marked UNVERIFIED below must be checked before the build.

CRITIC FIXES APPLIED: row is a button (aria option), so the Ctrl/Cmd test can press a row body. check is a button with selected for picked and its name for done (no checked flag). Search navigation expectations use rowBookBike and rowGroceries, with a stated active-match rule. The confirmDelete and cancelDelete parts and the delete-confirmation tests were removed (the sheet is outside this component; the critic's first fix). bulkDelete and menuDelete are kept as presence checks. The multi-selection row menu tests were removed (decision 6). Percentages other than exact values (25, 50, 0) were removed. The regex text matches became contains or exact text. The Ctrl/Cmd test is split from the plain press. The Title only highlight test asserts matchMark. The composer focus test was split out. The Escape test now checks the existing subtasks. collapsed-all was renamed collapse-one. The Show completed test asserts only what the sources support. The cross-list tests check the list switch and the preview. Rebuild-only event expectations were kept for the cross-list and search cases, and the event declarations say they are rebuild-only. The keys are Slash and KeyB/KeyZ. The attachment test passes project. The long scroll uses two scroll steps. The Option-click test carries the done-lamp record, and the duplicate record test was dropped. The removed tests that depended on the dialog are noted below.

PROPS (harness meaning):
- dataset: standard, empty or long. The harness signs in as the demo account and loads that data set before mounting. nolists was left out of the allowed values because no test uses it.
- project: Home or Spring launch. The harness opens this project before it selects the list. Added because the Website test needed it (critic fix).
- list: the list name inside the active project. The harness selects it by name before the screen renders.
- showCompleted: false sets Show completed tasks off for the account before mount.
- split: true mounts the pane as the left pane of a split view, so Close split shows. The reference shows Close split in no state, so this setting is unverified.

EVENTS: rebuild-only checks. The reference emits none. The format does not define how a comparison treats event expectations, so they are checked on the rebuild only. filterToggled was dropped (no decision, reference or feature behind it; the sort panel is outside this screen). copied, draftStarted and splitClosed rest on feature or decision records; taskPreviewed and listOpened rest on decision 3 and the search tests.

PARTS AND ROLES: the names are the clearer ones used by both drafts, with B's names for the scope and field items. Map rules applied: option to button, menuitem and menuitemradio to button, listitem to generic, list to generic, menu to generic, and the dialog-free roles only. The count parts (matchCount, doneCount, selectionCount) are status. The doneCount role changed from generic (A) to status (B). The round check is a button, not a checkbox, because the picked state needs selected (critic fix).

STEP SEMANTICS (assumed; platforms.yaml was not read, so the harness must define these):
- modifierHold: holds Option (Alt on the web) for the following steps of the test.
- selectToggle: holds Ctrl (Linux and Windows) or Cmd (macOS) for the next press.
- dismiss: sends Escape.
- do: scroll with with.direction: the scroll form comes from draft A. The scrollArea role is generic (aria list). The format says only hover is an action for generic parts, so the scroll advertisement is unverified. The test uses two scroll steps in case one does not reach row 40.
- A key step on a part focuses that part first, then sends the key.
- selected on a button: unverified (draft A flagged it too).
- Space and Alt+Space on a focused button may also fire that button's native press; the tests expect the screen's key handling only.
- record needs a motion step: the Option-click press starts it.

ACTIVE-MATCH RULE (assumed, stated for the search tests): typing does not activate a match and emits no preview. The first Enter moves focus to the first match in tree order (Book bike service), each Enter moves to the next match and wraps, and Shift+Enter moves to the previous match. Each move emits taskPreviewed. This rule makes both critic-checked expectations hold: the two-Enter test ends on rowGroceries and the Shift+Enter test ends on rowBookBike with three previews. The rule depends on row order (below).

ROW ORDER AND STANDARD DATA (UNVERIFIED): the visible root order is Pick up prescription, Post the parcel to Mum, Book bike service, Cut a spare key, then Buy groceries for the week (the parent, last), taken from the inventory's screenshot coordinates as draft A states. web.md lists Buy groceries first. The bulk and move tests and the rowBookBike focus depend on this order. Search "b" matches Book bike service and Buy groceries for the week, which assumes the unnamed third subtask has no b. Whole project "b" count 3 (Errands 2 and Reading 1, Return library books) assumes no other Home list has a b match. Whole project "the" count 5 is UNVERIFIED (the critic says it depends on note text not in web.md). Long data set 10/48 is UNVERIFIED (no source). UNVERIFIED, flagged by test or part: renameField placement, and whether typing replaces the existing title (the test assumes the inline field opens with the whole title selected); the bulk verb labels Mark done and Mark not done (the review did not say whether only the title changes); the group heading text (inferred from list names); the no-matches empty state (code path only); the attachment badge; whether Alt+N is the New task binding (draft A's critic-based reading of decision 18); whether the F08-031 F2 key is the title-edit trigger (area-08 records the trigger as uncertain; the Enter alternative in the critic's list is not in the sources read, so no test uses Enter for rename).

COLOUR AND VIEWPORT: colorSchemes is light only, because F07-104 says light appearance in this capture and B says the reference has no dark capture for this screen. Draft A's dark screenshots would have had no reference. The viewport is 860 by 768. The width is measured in the inventory; the height is estimated and not measured.

- Delete confirmations and Trash (dialog outside this component; the critic said to remove them). The Delete key with a picked task (F08-021) is dialog-dependent and not tested. Enter-not-confirm (decision 10) and Cancel default (decision 13) are dialog behaviours and not tested here.
- Multi-selection row menu (decision 6).
- Sort & filter panel contents and filter events (outside the screen).
- New task draft contents, subtask-row click into the preview, and the Copy toast (outside the screen).
- Wrap at top and bottom (F08-023): the wrap behaviour is not in the drafts.
- Blur dismissing the composer (F01-084): no step form for blur.
- Add subtask un-collapsing a collapsed parent (F07-050): no More button on a parent is defined, so no test reaches it.
- Done tasks keeping position (F01-079) is covered only by the Option-click test's row check.
- Move-up and move-down shortcuts, and select-all bindings beyond Control+KeyA (F08-020, F07-045): per-platform bindings are not in the files read.
- Desktop-only items (Cmd+F, Cmd+N, the capture hint, the Screenshot slot) per web.md.
- nolists dataset, no feature described.
- Layout measurements (F01-033, F01-081): screenshot only.
- Trash, undo, toast and API-failure items (F07-010 to F07-020, F07-023 to F07-034): outside this screen.
- Split-pane stats (F01-082), the draft inspector (F01-080), and the global shortcuts (F08-003 to F08-015): outside this screen.
