# How the app.contextmenus contract was written, and what its props make the harness do

BASED ON
- Draft A and Draft B (both as given in the task), and the critic's list, whose fixes are applied. I did not open any spec file. Source references (feature ids, decision numbers, notes replies, spec/screens/web.md data) are taken from the drafts and the critique as written, not re-checked.

HARNESS MEANING OF THE PROPS
- dataset (string, default standard): the harness signs in as the demo account and loads the named demo data set (spec/screens/web.md) before it mounts the screen. These tests use standard only (Home: Errands, Reading, Garden; Spring launch: Website, Press kit). The other demo sets are not used here, so they are not listed as values; the Draft B clamp test that needed long was dropped (see below).
- No other context prop. The screen starts with no menu open and opens on Home > Errands by itself, so no list, project or open prop is set.
- keyboard: false is set explicitly (Draft B had none). The automatic keyboard check would expect Enter on Move, Delete list and Delete project to act like a press, which contradicts decision 10. Keyboard paths are written as explicit tests.
- viewports 1180x760 and colorSchemes [light] (no dark state recorded).

SCOPE
- The contract is for the web build. No only: field is used, because the format's allowed fields for only were not confirmed; the scope is stated in the header instead. Desktop right-click is not contracted here.

DROPPED (and why)
- Right-click tests (Draft B: right-click opens the row menu at the pointer; right-click outside closes it; reference row-context-menu by right-click). Right-click is not an opener on web (Draft A, notes reply), and the do: contextClick action is not in the action list of contract-format.txt. The checkBike part went with them. The row-context-menu reference state is now screenshotted on More on Book bike service (web opener for the same menu).
- Bottom-edge clamp test (Draft B, long data set, do: scroll), and the moreLastRow and taskList parts: scroll is not in the action list. The long data set is therefore unused.
- Draft B: "Enter with an empty subtask title dismisses the composer". No feature record was cited for it, and the critic found none. Drop until a record is cited.
- Draft B: tabErrands and tabGarden text checks in the tab-menu test. They are list tabs visible without any menu, so they do not test the menu. tabErrands and tabWebsite parts are replaced by firstTab. tabGarden is kept as a visibility check after deletes.
- Draft B: Control+KeyA select-all for the rename. Select-all is not in the input vocabulary and the macOS mapping is unknown. The rename test types the new title and checks the exact result (see uncertain item b).
- Draft A: selected checks on projectHome and projectSpringLaunch. selected may not be measured on menu rows. The current project is checked through the switcher text instead.
- Draft A: exact Delete project headline text and the Rename project accept label, both from source text not in the recorded inventory. Replaced by headline contains "Spring launch"; no label check on those two.
- Draft B: "puts it back" in the Move to Trash hint. The recorded wording (F07-079 title) is "puts a trashed task back"; that string is used, with contains, because the shortcut key name differs by platform.
- Draft B: the bulk menu for a multi-selection is not in the contract (see open conflict 2).
- Draft B: the "generated name" check on New project was reduced. The vocabulary has no value-matching check, so only the accessible name (label) is checked. The generated value is not checked.
- Draft A: bulk menu was not dropped as settled; it is an open conflict, not a decision.

NOT COVERED ON PURPOSE (with reason)
- Right-click on web (F06-042, F06-052, F07-065): open conflict 1; no contract action.
- Bottom-edge clamp (F06-039): needs a scroll action not in the vocabulary.
- Submenu side flip (F06-049): the widest submenu ends near x 1139, short of the 1176 limit at 1180x760.
- Move to list disabled (F06-051): no one-list project in the demo data has a task to open a menu from.
- Window blur and resize (F06-043): no action can cause them.
- Focus trap (F06-069): the Tab order of sheet buttons is not recorded.
- Count label on a single delete (F07-031): wording not recorded.
- Dice (F06-079, F06-080): no part for a Dice control; the critic asked for a check only if Dice is on the New project sheet, which is not confirmed.
- Export list and Open in split view results: not recorded; only the menu closing is checked.
- Toast timer (F06-095): no wait step.
- Multi-selection bulk menu: open conflict 2. The multi-context-menu reference state is therefore not covered; the single-row menu on Cut a spare key is screenshotted under its own name (single-row-task-menu).
- Dark colour scheme: none recorded.
- Drag and drop (F07-039 to F07-045): excluded by the rule that drag acts only on sliders.

OPEN CONFLICTS (decisions needed; decisions.md has no numbered entries for these, and a contract cannot cite the review notes)
1. Web right-click. The critic notes that web.md keeps the reference behaviour except where web.md or decisions.md say otherwise, so F06-042, F06-052 and F07-065 still apply on web unless a numbered decision drops right-click. This contract tests More only.
2. Bulk menu for a multi-selection (notes reply) versus decision 6 (bulk actions in one place only). Decision 6 does not clearly cover right-click menus. Unresolved.
3. Move to list opens on click (overrides F06-046, where a click does nothing). Marked "open:" in the test name.
4. Escape and ArrowLeft return from the submenu to the parent (overrides F06-040 as written). Marked "open:".
5. More buttons on the tab rows and project rows (web additions from the notes). Their rest visibility is not recorded; only the Reading tab More is tested.
6. Owner-only rename and delete of projects (decision 9). The demo account owns both projects, so no non-owner case is testable.
7. Title edit: whether it commits on Enter, and whether typed text replaces the existing text (F07-054, F06-075). Several exact checks depend on this.
Action: add numbered entries to decisions.md (or web.md) for items 1 to 5, then remove the "open:" marks.

UNCERTAIN, TO VERIFY IN THE REBUILD OR THE HARNESS
a. The sheets (Move to Trash, Rename list, Delete list, Rename project, Delete project, New project) must be mounted with this screen; otherwise every sheet step fails.
b. Typed text replaces the pre-filled or selected text in the title editor, Rename list, Rename project and New project (F06-075, F07-054). Exact checks will fail if it appends.
c. Enter commits the title edit (commit key not recorded).
d. Picking a project-row item closes the dropdown; the tests reopen it with projectSwitch.
e. Absent parts: visible false on moveErrands (never present), rowEggs before creation, and rowPrescription and rowBikeService after a move or delete. This assumes the harness reports an absent part as not visible; if not, these checks are not measured.
f. Key names Space, Tab, Backspace, Escape, Enter, ArrowLeft and ArrowRight follow the harness vocabulary (unchecked against platforms.yaml). The named inputs (dismiss, submit, confirm) are not used because the format's own example uses raw key names.
g. The record: true field form (see added items).
h. subtaskTitle: the demo data may already hold a subtask under Book bike service (Draft B said "the first subtask"); the test checks for the subtask it adds, so the check holds either way if the new one shows.
i. The exact container of the Move to Trash hint text (sheetDetail) is assumed.
j. Exact text checks on rowPrescription, rowBikeService, tabReading and projectSpringLaunch assume the row or tab text is the title only. If rows carry more text, these become contains checks.
k. Delete list headline uses contains "Delete “Reading”?" from Draft A (quotes as given).
l. rowEggs is not in the demo data; the test creates it. moreGroceries is the first row More button (Buy groceries for the week).
m. The toast replacement test assumes the second delete's More stays reachable while the first toast is up.
n. The Delete list and Delete project Escape and Enter tests, and the Move Tab-then-Space test, follow the critic's wording; their steps have not been run.
