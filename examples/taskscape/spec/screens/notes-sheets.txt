# Review notes on the sheets screen (the team's comments and how each was settled)

- [desktop] Opus (orchestrator): On the desktop version every sheet becomes its own window (new list, new project, rename, confirmations), with no backdrop dimming the main window. The backdrop was a workaround for Tauri, where opening windows lags.
  - reply (Haiku review): Decided. On desktop every sheet is its own window with no backdrop dimming the main window, so the Scrim and Background window regions drop out for desktop. The reference Sheet is one card over a soft Overlay, so the Sheet content moves into its window unchanged.
- [web] Opus (orchestrator): On the web these stay in-page dialogs over a backdrop, which is the platform's own idiom.
  - reply (Haiku review): Decided. On web, sheets stay as in-page dialogs over a soft scrim, as the reference does. The brief makes separate windows a desktop rule, and the same Sheet widget serves both builds, so only the desktop wrapper differs.
- [both] Haiku critic: Destructive confirmations use different tones and verbs. delete-list uses a danger-tone badge and a red 'Delete list' button, while delete-confirm ('Move to Trash?') uses the accent tone and a neutral 'Move' button. Both delete something, so the same job is styled two ways without a clear reason; consider one destructive tone and verb pattern for both.
  - reply (Haiku review): Decided. Both destructive confirmations take the danger tone. Delete-confirm drops its accent badge and gets a danger accept button labelled 'Move to Trash' instead of 'Move', and the bulk Trash sheet gets the same treatment. Delete list keeps its 'Delete list' label, and accent blue stays for primary actions and selection only.
- [both] Haiku critic: The Cancel button is 84px wide on the name sheets and delete-confirm, but 100px on delete-list (556,403). The code sets min-w-24 (96px) on grid buttons, which matches neither measurement. The variant width is unexplained and should be fixed to one value in the rebuild.
  - reply (Haiku review): Answered. The root font size is 14px, so 1rem is 14px and min-w-24 (6rem) is 84px, which matches the name-sheet and delete-confirm Cancel widths. Use one 6rem minimum for every footer button with equal grid columns. The 100px Cancel on delete-list most likely comes from the column stretching to its wider 'Delete list' label, and the 96px in the inventory is wrong; check this during the rebuild.
- [both] Haiku critic: Project deletion and rename have no sheet state. F09-014 (delete a project, confirmed by a count of its lists and tasks) and F09-013 (rename a project) are in the feature list, but the delete-list copy is fixed to one list ('Its 3 tasks go with it') and no project sheet or count variant appears. Add a project delete variant with the list and task counts, or state where it is handled.
  - reply (Haiku review): Answered. The reference has both project sheets and the inventory missed them. Rename project prefills the current name and accepts 'Rename'; Delete project counts the lists and tasks and asks a danger sheet 'Its N lists and M tasks go with it. No undo.' with accept 'Delete project'. Add sheet-rename-project and sheet-delete-project states to the inventory, with singular, plural and empty count variants.
- [both] Haiku critic: The danger accept button ('Delete list') is not guarded. There is no ask on this sheet, so Enter runs accept and deletes the list at once, and the delete-confirm 'Move' has the same immediate-Enter behaviour. For destructive actions, the rebuild should make Cancel the default Enter target or require an explicit click.
  - reply (Haiku review): Needs Mujtaba. In the reference, the window Enter handler runs accept and delete-list has no ask step, so Enter deletes the list at once. One review treats the behaviour as an open product choice, while the other treats it as settled by the reference's danger and focus rules, so the product owner needs to choose.

Question: On destructive confirmations (Delete list, Delete project, Move to Trash), should Enter (a) run the destructive action as the reference does, (b) move initial focus to Cancel so Enter cancels and the danger button needs a deliberate Tab or click, or (c) be ignored so only a click confirms? Prompt sheets keep Enter-to-accept under (b).
  - reply (Opus (orchestrator)): Decided with Mujtaba (14 Nov), decision 10: Enter on destructive confirmations: Enter does not confirm. Delete list, Delete project, Move to Trash, Empty Trash and Delete permanently need a click on the danger button, or Tab to it and Space. Escape cancels. Prompt sheets (new list, rename…) keep Enter to accept.
- [desktop] Haiku critic: The desktop version must not draw a scrim, dim the main window, or dismiss on a press outside the card. Each sheet should open as its own modal window, with Escape and Cancel closing it, and the 'Background window' and 'Scrim (Backdrop)' regions should be dropped for desktop.
  - reply (Haiku review): Decided. On desktop each sheet opens as its own window, modal to its parent so the main window is blocked while it is open. Escape and Cancel close it, and an outside press has no meaning because there is no scrim. The Scrim (Backdrop) and Background window regions are dropped for desktop.
- [web] Haiku critic: The delete-confirm detail line says '⌘Z puts it back' and the Toast Undo action (F06-093) depends on a global undo shortcut. In the web version browser shortcuts take precedence and there are no global hotkeys, so the copy and recovery path should use an on-screen Undo control in the toast, not a keyboard shortcut.
  - reply (Haiku review): Decided. On web the detail line drops the '⌘Z puts it back' hint, because browser shortcuts take precedence and there are no global hotkeys. Recovery is the toast's on-screen Undo button, which calls history undo directly and needs no shortcut. Desktop keeps ⌘Z.
- [web] Haiku critic: The 'Import JSON…' instead action reads a local file in the reference, but the web version is a cloud app where files are uploaded to the server. The web import needs an upload step with its own error and progress states, and the inventory has none.
  - reply (Haiku review): Decided. On web, Import JSON opens a file input limited to .json and uploads the file to the server rather than reading a local path. The sheet shows a progress state and an error state for cases such as invalid JSON or a failed upload, since the reference has no error path (importList has no catch). The desktop path keeps the system file dialog, and the inventory should list both new states.
