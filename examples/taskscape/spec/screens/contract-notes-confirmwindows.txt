PROPS AND WHAT THE HARNESS DOES.
- dataset: the parent main window is seeded with the named demo data (standard, empty, nolists, long) before the window opens. No sign-in on desktop.
- open: the parent main window is mounted with dataset, then exactly one window is opened over it as its own OS window. The parent must be mounted so that changed can be read (the critique asks for one mount rule; this is it, and it is the rule that allows parent effects to be tested). Values are camelCase versions of Draft A's kebab names (new-list becomes newList, and so on). Targets when target is "": renameList and deleteList use list Reading (standard) or Inbox (empty); renameProject and deleteProject use Home; moveToTrash uses "Book bike service" (Errands); emptyTrash and deletePermanently use the Trash rows of standard. deletePermanently selects the two Trash rows "Print the old flyer" and "Call the printer about samples" (names from Draft B, not re-checked).
- count: moveToTrash and deletePermanently only. The harness rejects deletePermanently with count below 2 (decision 12). For moveToTrash with count 3 the harness selects the first three open tasks of Errands, starting with "Book bike service" (the critique's requested definition). The standard count of Errands tasks is not given by the sources; the long dataset has 45 there.
- target: the exact name of the list, project or task. Used by renameList, deleteList, renameProject, deleteProject and moveToTrash. Tests that pass target: "Spring launch" (project, standard), "Buy groceries for the week" (task, standard) and "Inbox" are names from the drafts; they are not checked against the data.
- initialName: the one starting-text seam. newList and newProject only. The harness sets the field's starting text, selected, before the window shows. "" leaves the app's roll in place. This replaces Draft A's name-pool seeding, so there is one mechanism (critique item on the seam). If the app has no starting-text seam, the parent must add one; until then the initialName tests are not runnable.

VIEWPORTS. The viewports list is not a run list. The harness sizes each window from its open value: prompts (newList, newProject, renameList, renameProject) 364 x 141; confirmations (deleteList, deleteProject, moveToTrash, emptyTrash, deletePermanently) 364 x 122. The 141 is measured for the prompts and the 122 for deleteList only; the other windows take their kind's size, which is an assumption. The parent should confirm this rule or split the contract into prompts and confirmations.

EVENTS. answered: action accept | dismiss | instead; text is the trimmed name for prompts and "" otherwise; id is the spec's instead id and is not asserted, because the Import JSON press was dropped (see below). changed: the data change an accept made in the parent's data, read through the mounted parent. Exceptions: the names "Trash" (trash-emptied) and "2 items" (purged) have no single name, so the harness uses these; the sources do not give them. PARENT TO CONFIRM: whether the window emits changed or the parent contract owns it. If the window does not emit it, the times 1 checks fail and the times 0 checks pass vacuously, so changed must be removed from this contract or confirmed.

PARTS. detail is required on deleteList, deleteProject and moveToTrash, and expected on emptyTrash and deletePermanently (copy unconfirmed). Prompts have no detail and no test reads it there. field, roll and instead are optional. Their visible: false checks are absence checks on optional parts; per the critique the engine skips these with a note, so they assert nothing where the part is absent by design. The parent should decide whether to make them strict. The glyph is the badge part; its visibility is not checked (aria-hidden), only screenshots show it.
