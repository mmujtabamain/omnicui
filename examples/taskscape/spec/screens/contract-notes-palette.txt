# How the app.palette contract was written, and what its props make the harness do

Based on: Draft A (palette tests, rowDelete, the optional-part and dataset/task props, the left-out list) and Draft B (the ran event, the scrim and results parts, the hover-then-Enter test, the Delete run test, the left-out list with reasons), with the critic's fixes applied. Both drafts cite the same sources: spec/inventory/command-palette.json (1180x760 measurements, label and placeholder text, the 19 palette rows in five groups), the palette feature records F06-001..F06-037, F06-083..F06-090, F08-010, F08-043..F08-049, F08-061, decisions 7 and 18, review notes 1, 5, 6, 11, 12, 13, 14, 15, 16, and spec/screens/web.md. Source files were not reopened for this merge; the facts come from the drafts and the critique.

Harness meaning of the props:
- dataset: the harness signs in as the demo account, loads the named data set (standard default; empty, nolists, long allowed), and mounts the palette open with an empty query. No test varies it, because the other data sets have no palette reference. The prop is kept because the screen contract always declares dataset.
- task: "" selects nothing, so no Delete row is listed. A title makes the harness select that task in the focused list the way a user does, then mount the palette, so the Delete row is listed. The title must exist in the data set, or it is a harness error. Draft A used "Rewrite the hero section" (Website, in the Spring launch project), which would switch project and could change the Go-to-list rows. The merge uses "Buy groceries for the week" (Errands, the open list), per the critique.

Harness meaning of the event ran: a harness-only event, not in the reference. The rebuild emits it on every command run (row click or Enter) with the row's visible text, after the panel has closed. Escape emits nothing. Parent decision needed: the reference target cannot emit it, so event expectations fail or are unmeasured there. If the event stays, the event tests should be restricted to the web target, but the format's syntax for that is not confirmed here. It is kept because it is the only way to observe which row ran and which row is highlighted, and the critique's first fix depends on it.

Format assumptions:
- Key steps take no times. Repeated presses are written as separate steps (Draft A's ArrowDown 25, Up 5, Down 3, Backspace 3, Tab 3; Draft B's ArrowDown 18). The 19-step run is the clamp test, based on Draft B's count that Spring launch is the 19th row (index 18).
- rowDelete is optional. Draft A's comment says checks on an optional part are skipped when it is absent. The rowDelete visible:false check is kept as the critique asks, but it may be skipped. The emptyMessage check in the same test carries the absence claim.
- scrim is a generic part, so only its visibility is checked. Its outside press is not expressible (a generic part accepts only hover). Mapping it to button would invent a role. Parent decision: add an outside-press action or a button-role scrim, or leave the scrim to the screenshot.
- The row role is button, with aria option in the comments, per the inventory's elements.json. The panel is generic with aria dialog, and results is generic with aria listbox.

Merge: the union of both drafts' tests, with duplicates and wrong checks removed.

Dropped (with reason):
- keyboard: true (Draft A): the generated Enter and Space checks would press rows, which are not focusable.
- Constant-text highlight checks (Draft A: row "Toggle preview" in the reset, ArrowUp and hover tests; rowSpringLaunch text in the ArrowDown test): they pass whether or not the highlight moved. Replaced by ran-event checks.
- Draft A "Enter after a typed query runs its first match": duplicate of the reset test, which also ends with Enter after "new" running New task.
- Draft B "matching is by substring, not fuzzy" (tgl): the rule is not sourced in the allowed sources, and tgl would match under fuzzy matching.
- Draft B do: scroll on results: the action is not confirmed for a generic part, and note 15 (cited) concerns web shortcuts, not palette scrolling. The keyboard-driven scroll test covers scrolling.
- Draft B groupHeading: duplicate of groupView.
- Draft B separate palette-state and palette-search screenshot tests: merged into the opening and typing tests, so each reference state keeps one screenshot.
- Draft B typed "preview", "split" and "swap" run tests: covered by the first-row Enter test, the ArrowDown test and the hover test.
- Draft B "Enter with no results" test: merged into Draft A's combined no-match test.
- Draft B "Enter runs the highlighted row" typed variant, and "the highlighted row scrolls into view and Enter runs it": merged into the 19-step clamp test and the scroll-visibility test.
- Draft A groupGoList and groupGoProject visible headings at open and in the clearing test: clipped below the 60vh cap, so removed. groupGoProject is asserted only after scrolling.
- Draft B "matching ignores case" is kept as a plain match test (capitals query), with the rule flagged as unconfirmed.

Conflicts and how they were resolved:
- Task title: Draft A "Rewrite the hero section" vs Draft B "Buy groceries for the week". Took Buy groceries (see task above).
- Delete row: Draft A has a rowDelete part, Draft B has none. Added rowDelete as an optional part.
- F06-090 (window blur or resize dismissal): Draft A says it is desktop-only per the review; Draft B says dismissOnWindowChange is the context menu's setting per the inventory. Kept Draft B's reason because it is the more precise source. The conflict is unverified; Draft A's reason is recorded here.
- Matching rule: case-insensitive matching appears only in the capitals test. Substring-only matching was dropped. The rule is unconfirmed in the cited records.
- Web hints conflict: decision 18 gives web defaults of Alt+N (New task), Alt+Shift+N (New list) and "/" (Search this list). Review notes 5 and 6 say ⌘F, ⌘N and ⌘⇧N are not shown on web rows, ⌘Z and ⌘⇧Z stay, and the rest must be checked in the browser. Not reconciled, so no hint is asserted. Screenshots compare the reference hint column and may differ on web. Needs a decision from the spec owner.
- Row height: the [both] review sets 32 px for every row; the reference's no-hotkey rows are 30 px. Screenshots will differ by design.
- Errands (Draft A, jump row) and Home (Draft B, go-to-project row): both kept as separate runs. The Errands group is not asserted.

Left out, with reasons:
- Opener (Ctrl/Cmd+K, title-bar control, F08-010): belongs to the app shell; the palette is mounted open.
- Scrim press dismissal (F06-018, the scrim half of F08-048): format gap (see scrim above).
- F06-003 (catalog built once per open): no visible output; reopening needs the opener.
- F06-016, F06-017, F08-045 (icons, hint glyphs): icons carry no text, so only the screenshot covers them.
- F06-087 (depth counter), F06-088 (focus returns to the opener), F06-089 (focus parked on the scrim, which never fires because the input takes focus on open), F08-061 (app key map while open): effects are on the app outside the palette or on the opener, which this harness does not mount.
- F06-019 (overlay focus trap): not observable standalone. The Tab test checks that focus stays on the search input.
- F06-021..F06-033 (command effects): each run test checks the event label and that the panel closed. Effects belong to the target screens. Settings (F06-033) now has a run test. The other commands use the same close path, so they are not each re-tested.
- F06-090: see the conflict above.
- F08-043 (top placement at 12vh, centred): covered by the opening screenshot only; not asserted in text.
- Wheel scrolling: no wheel action in the format.
- Dark scheme: no dark reference exists, so light only. The code has dark classes.
- Desktop separate window, no scrim, blur dismissal: not this web contract.
- Context menu, sheets, toasts and overlays: other screens.
- Events other than ran: the inventory declares none for the palette.
- Drag-and-drop: none on this screen.

Open items, not asserted:
- Delete row label "Delete “<task title>”" comes from the review notes and F08-044. Its icon is unresolved (review note 13, palette source not opened). Its placement after Settings under the Task heading is from notes, not a recording. Both drafts agreed on the label, which stays an assumption to confirm.
- The ran event and the matching rule need the parent decision above before the contract is final.
