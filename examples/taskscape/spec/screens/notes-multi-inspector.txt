# Review notes on the multi-inspector screen (the team's comments and how each was settled)

- [both] Haiku critic: The inspector's Done, Undone, Move, Copy and Delete ToolbarButtons duplicate the bulk bar's Done, Undone, Move to..., Copy and Delete buttons, so one job has two widgets. The labels differ (Move vs Move to..., Copy vs Copy as checklist, Delete vs Delete selection) and only the bulk bar's Move is recorded with an ellipsis. Pick one set of labels and one widget per verb for the rebuild, or state why the two are different.
  - reply (Haiku review): Needs Mujtaba. Both reviewers agree the duplication is real, since the inspector verb grid and the bulk bar are on screen together and both use ToolbarButton. The visible labels match except Move versus Move to…, and the Copy and Delete wording differences are tooltip text only. Inspector Copy shows Copied feedback (F04-023) while bulk Copy shows none (F07-062), so whether both surfaces stay is a product call; Reviewer A recommends the bulk bar labels in both places if both stay.

Question: When several tasks are selected, should the bulk verbs (a) keep both the inspector verb grid and the bulk bar with one label and one widget per verb, (b) keep only the bulk bar and move Open and Clear selection into the inspector, or (c) keep only the inspector grid and drop the bulk bar while the inspector is open?
  - reply (Opus (orchestrator)): Decided with Mujtaba (14 Nov), decision 6: Bulk actions: one place only, the bulk bar. The multi-select inspector shows the selection (count and the selected tasks) with Open and Clear selection, and no verb grid. The same job no longer has two widgets.
- [web] Haiku critic: The footer hints '⌘\' for hiding the preview panel and '⌘,' for Settings are global-style shortcuts. The web build must let browser shortcuts take precedence, so these keys may not reach the app, and the hint text should be shown only where the shortcut actually works. The desktop build keeps both shortcuts.
  - reply (Haiku review): Decided. The ⌘\ and ⌘, hints are title-bar tooltips for Hide preview panel and Settings, not footer hints, and the reference builds each from the live binding so an unbound command shows none. The brief says browser shortcuts take precedence on web, so the web build does not promise these keys and shows a hint only where a key is actually bound, which drops both by default. Desktop keeps both hints, since the hide toggle and the Settings window run from these keys there.
